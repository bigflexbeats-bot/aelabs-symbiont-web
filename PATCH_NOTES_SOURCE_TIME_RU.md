# Исправление времени и тренда AELABS WEB

- При настроенном GIT LOG тренд и таблица читают строки непосредственно из `data/log/aelabs_log.csv`; время берётся из `source_time_raw` или `event_time_utc` внутри CSV. Без настройки репозитория используется fallback по `latest.json`.
- Без CSV повторный опрос одного и того же `latest.json` больше не добавляет синтетические точки. В CSV повторяющиеся строки с тем же исходным временем и показаниями схлопываются.
- Изменение только `received_at_utc` не считается новым измерением.
- `received_at_utc`, время получения файла и локальные часы браузера не используются для меток точек.
- Для временной оси используется timestamp источника. При разрыве между наблюдениями более 30 секунд линия не соединяется через пропуск; отсутствующее значение параметра также разрывает соответствующую серию.
- Если в свежем снимке поле измерения временно отсутствует, карточка сохраняет последнее читаемое значение.
- История старого формата с точками, созданными по каждому опросу браузера, больше не загружается. Новая браузерная история начинается чисто, сохраняя только уникальные наблюдения с исходным временем.
- В legacy snapshots поле `timestamp` из содержимого Git-файла интерпретируется как время источника; поле `received_at_utc` заполняется только при его явном наличии.

- Для подключения CSV из Render доступны `GITHUB_LOG_OWNER`, `GITHUB_LOG_REPO`, `GITHUB_LOG_BRANCH`, `GITHUB_LOG_PATH`, `GITHUB_LOG_TOKEN`. Токену достаточно Contents: Read-only.
- История обновляется автоматически каждые 15 секунд; карточки LIVE продолжают обновляться каждые 5 секунд.
