# AELABS SYMBIONT WEB — read-only monitoring

Веб-панель отображает телеметрию настольного AELABS MONITORING. Управление оборудованием через сайт не реализовано и в первой версии не предусмотрено.

## Источник данных

По умолчанию сервер читает приватный репозиторий `bigflexbeats-bot/aelabs-symbiont-data`, ветку `main`:

- `data/live/latest.json` — последний снимок;
- `data/history/**/*.json` — архив наблюдений.

API совместим с текущим форматом издателя `symbiont-observation/v1`, в котором `latest.json` содержит объект `observation`, и с прежним форматом, где поля наблюдения находятся на верхнем уровне. Токен GitHub не отправляется в браузер.

## Локальный запуск

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
# Windows PowerShell: $env:GITHUB_TOKEN = 'ваш_read-only_token'
# Linux/macOS: export GITHUB_TOKEN='ваш_read-only_token'
python app.py
```

Откройте `http://127.0.0.1:8080`. Для реального доступа к приватному репозиторию необходим fine-grained GitHub token с доступом только к репозиторию данных и правом **Contents: Read-only**. Не помещайте токен в исходники, HTML, JS или публичные коммиты.

## Деплой на Render

1. Загрузите содержимое этой папки в репозиторий `aelabs-symbiont-web`.
2. На Render выберите **New → Blueprint** и подключите репозиторий с `render.yaml` либо создайте **Web Service** вручную.
3. Для ручного создания задайте Build Command `pip install -r requirements.txt` и Start Command `gunicorn app:app --bind 0.0.0.0:$PORT`.
4. В Environment Variables задайте `GITHUB_TOKEN` (Secret), `GITHUB_OWNER=bigflexbeats-bot`, `GITHUB_REPO=aelabs-symbiont-data`, `GITHUB_BRANCH=main`.
5. После успешного деплоя проверьте `/api/health`, `/api/latest` и `/api/history`.

Render автоматически может разворачивать новые коммиты связанной ветки. Бесплатные экземпляры могут засыпать при бездействии; это нормально для прототипа, но не для критически важного непрерывного мониторинга.

## API

- `GET /api/health` — проверка доступа к источнику;
- `GET /api/latest` — нормализованное последнее наблюдение;
- `GET /api/history` — последние архивные записи.

Чтобы не расходовать лимит GitHub API, LIVE-снимок кэшируется на 4 секунды, браузер обновляет карточки каждые 5 секунд, а CSV-история — каждые 15 секунд с серверным кэшем. При настройке GIT LOG веб читает строки из отдельного `data/log/aelabs_log.csv`; таблица и тренд используют точное время из столбцов `source_time_raw`/`event_time_utc`. Повторные строки с тем же исходным временем и теми же измерениями схлопываются, `received_at_utc`, время получения файла и локальные часы браузера не создают точки. Разрыв более 30 секунд на графике не соединяется непрерывной линией. Если GIT LOG не настроен, используется ограниченный браузерный fallback, который тоже добавляет точку только при наличии новой записи с исходным временем. Веб-сервер работает только на чтение и не пишет данные в репозиторий.


## Обновление: тревоги и тренды
- Вверху панели отображаются активные ошибки и предупреждения, в том числе отсутствие новых записей более 10 минут, нарушения диапазонов pH, температуры, растворённого DO и O₂ в абгазе, а также quality flags источника.
- Веб-пороги по умолчанию: pH 6.5–8.0; температура 20–28 °C; растворённый DO 3–9 мг/л; O₂ в абгазе 3–9%. Они повторяют базовые значения настольного `aelabs_settings.ini`; веб-сайт работает только на чтение и не получает эти настройки автоматически из настольного ПК.
- При настроенном GIT LOG тренд и таблица строятся по последним строкам CSV из отдельного репозитория; параметры можно включать/выключать. При пропуске значения линия соответствующего параметра прерывается, а большие разрывы времени не соединяются. Без GIT LOG включается локальный fallback по уникальным записям `latest.json`.
- Новые файлы веб-сервиса развертываются обычным коммитом в репозиторий сайта. Для чтения CSV из отдельного GIT LOG репозитория нужно один раз настроить переменные Render из раздела ниже.


## История тренда из GIT LOG CSV

В Render задайте переменные окружения веб-сервиса:

- `GITHUB_LOG_REPO` — `owner/repository` (например, `chernushkindm-lab/symbiont_lab`; можно указать только имя репозитория и отдельно задать owner);
- `GITHUB_LOG_OWNER` — владелец репозитория, если `GITHUB_LOG_REPO` содержит только имя;
- `GITHUB_LOG_BRANCH` — обычно `main`;
- `GITHUB_LOG_PATH` — `data/log/aelabs_log.csv`;
- `GITHUB_LOG_TOKEN` — fine-grained token с **Contents: Read-only** только для репозитория GIT LOG. Если не задан, используется `GITHUB_TOKEN`, который тогда тоже обязан иметь доступ на чтение к этому репозиторию.

После redeploy проверьте `/api/history`: поле `storage` должно быть `github-csv`, а в `items` должны быть строки из CSV. Чтение кэшируется, чтобы не отправлять запрос в GitHub на каждый опрос страницы.

## Синхронизация ошибок настольного приложения

Веб-интерфейс предпочитает `desktop_status.active_alarms`, если поле `alarm_state_authoritative` равно `true`. При таком формате сайт отображает состояние сигнализации, опубликованное настольным приложением, а не вычисляет процессные ошибки по отдельным жёстко заданным порогам. Если поле отсутствует, используется обратная совместимость со старым форматом.

Чтобы ошибки и их восстановление отражались в вебе, обновите настольное приложение этой сборкой. Старые записи JSON без `desktop_status` не содержат полного состояния ошибок.


## Важно: источник LIVE-данных

Веб-код размещается отдельно в `bigflexbeats-bot/aelabs-symbiont-web`.
Настольное приложение публикует `data/live/latest.json` в репозиторий данных
`bigflexbeats-bot/aelabs-symbiont-data`, ветка `main`. Веб-монитор читает именно
репозиторий данных `bigflexbeats-bot/aelabs-symbiont-data` по умолчанию. Если на хостинге (например, Render) заданы переменные
`GITHUB_OWNER` или `GITHUB_REPO`, они имеют приоритет над значениями по умолчанию:
установите `GITHUB_OWNER=bigflexbeats-bot` и `GITHUB_REPO=aelabs-symbiont-data`.
Также нужен действующий `GITHUB_TOKEN` с доступом на чтение содержимого этого репозитория.

Для диагностики откройте `/api/health` и `/api/latest`. Если `/api/latest` возвращает
ошибку 401/403/404, сначала исправьте токен, права или путь к репозиторию; сам график
не сможет построить линию, пока веб не получает актуальный JSON.
